# 포트폴리오 전시장 데이터 형식과 입력 검증 기획

개인 설정, 작품, 아키텍처와 이미지의 저장 형식을 정의한다. 같은 자료가 갤러리, 3D 전시장과 작품 상세에 일관되게 반영되고, 친구가 가져오기와 내보내기로 자기 전시장을 유지할 수 있게 하는 기준이다.

자료 형식의 초안 버전은 `1.0.0`이다. 명세, JSON Schema와 예시 데이터에 더해 공통 생성·검증·조회 및 공개 선별 함수를 구현했다. 초안 저장과 이미지 실물 검사, ZIP 백업·공개 내보내기 및 확인 후 가져오기도 구현했다. 공개 파일과 초안 스냅샷을 사용하는 갤러리·상세 및 영상 연결을 구현했다. 개인 정보·작품·사례·이미지·구조 목록과 전시 설정 편집을 연결했다. 2D·3D 그래프 탐색을 연결했다. 3D 전시장도 연결했다. 템플릿 콘텐츠 반영·빌드 검사와 GitHub Pages 워크플로도 연결했다. 실제 계정 배포와 작품 콘텐츠 검증은 후속 확인 대상이다.

## 자료 묶음과 파일 구성

작성용 자료와 가져오기 자료는 하나의 JSON 묶음으로 정한다. 앞선 기획의 분리 파일 구성은 공개 출력에 적용한다. 편집 시 여러 파일의 작품 순서와 참조를 각각 바꾸지 않도록 한다.

```text
작성과 가져오기
  portfolio.json
    schemaVersion
    kind
    site
    projects
    architectures
    assets

공개 콘텐츠 패키지
  content/site.json
  content/projects.json
  content/architectures/작품ID.json
  content/assets.json
  assets/이미지파일
  export-manifest.json

전체 초안 백업
  backup.json
  portfolio.json
  assets/이미지파일
  export-manifest.json
```

`export-manifest.json`은 패키지 종류, 형식 버전과 파일 목록을 적는 내보내기 명세 파일이다.

전체 초안 백업은 모든 작품과 자산을 포함한다. 공개 콘텐츠 패키지는 공개 작품과 사용 중인 자산만 포함한다. 둘 다 정적 콘텐츠 자료이며 사이트 실행 코드 자체는 템플릿 저장소가 제공한다. 친구는 복제한 템플릿에 공개 콘텐츠를 반영해 배포한다.

### 자료 종류

| kind | 의미 | 공개 내보내기 |
| --- | --- | --- |
| workspace | 작성 중인 개인 자료 | 검증과 공개 대상 선별 후 가능 |
| public | 선별과 검증을 마친 공개 자료 | 공개 출력 생성에 사용 |
| example | 형식을 설명하는 기획 예시 | 허용하지 않음 |

`kind`를 수정하는 것만으로 자료를 공개로 전환하지 않는다. 공개 변환은 전체 검증과 정리 과정을 거친다. 예시는 예시 미리보기와 연습에 사용하고 실제 작품처럼 공개하지 않는다.

### 공통 표현

미확인 단일 값은 `null`, 서술형 입력 전 값은 빈 문자열, 목록이 없으면 빈 배열을 사용한다. `0`이나 자료 준비 중이라는 문구를 실제 값 대신 저장하지 않는다. 준비 중 문구는 관람 화면이 생성한다.

스키마에 정의된 키는 명시적으로 저장한다. 알 수 없는 키는 조용히 버리지 않고 버전 또는 필드 오류로 처리한다. 현재 형식에 없는 사용자 확장 필드를 이전 검증기로 가져왔을 때 원본을 보존하고 가져오기를 중단한다.

본문은 일반 텍스트로 저장한다. 줄바꿈은 보존하되 입력을 HTML로 실행하지 않는다. 한 줄 필드는 앞뒤 공백을 제거하고, 문단은 의도한 줄바꿈을 유지한다. 글자 수는 유니코드 코드 포인트 기준이며 화면 검증과 스키마 검증에서 같은 방식으로 계산한다.

## 개인 설정

| 필드 | 형식과 한도 | 공개 기준 |
| --- | --- | --- |
| profile.displayName | 문자열, 최대 40자 | 공백만 있는 값 불가 |
| profile.bio | 일반 텍스트, 최대 2000자 | 선택 |
| profile.avatarAssetId | 자산 ID 또는 null | 자산이 존재해야 함 |
| profile.interests | 중복 없는 문자열 목록, 항목당 60자 | 선택 |
| profile.links | 링크 목록 | 라벨과 HTTPS 주소 필요 |
| exhibition.title | 문자열, 최대 80자 | 공백만 있는 값 불가 |
| exhibition.description | 문자열, 최대 300자 | 선택 |
| exhibition.defaultView | gallery 또는 exhibition | 기본값 gallery |
| exhibition.projectOrder | 작품 ID 목록 | 모든 저장 작품의 ID를 정확히 한 번 포함 |
| theme.preset | digital 또는 light | 미리 정한 테마 |
| theme.logoAssetId | 자산 ID 또는 null | 선택 |
| theme.faviconAssetId | 자산 ID 또는 null | 선택 |

공개 자료의 `projectOrder`에는 공개 작품만 남긴다. 작품 공개 여부는 `project.status`가 기준이며 별도의 `publishedProjectIds` 목록을 저장하지 않는다. 이는 기존 기획의 제안 필드를 구체화하면서 중복 상태를 제거한 결정이다.

프로필 이미지를 선택하지 않으면 기본 표시를 사용한다. 현재 사용자 업로드는 PNG, JPEG, WebP와 AVIF로 제한하는 방향으로 정한다. 템플릿의 기본 로고와 파비콘은 실행 코드가 제공하는 별도 자산이다.

## 작품 기본 정보

| 필드 | 형식과 한도 | 기준 |
| --- | --- | --- |
| id | 소문자 영문과 숫자 및 하이픈, 최대 64자 | 등록 시 생성하고 이후 유지 |
| slug | id와 같은 형식, 최대 64자 | 공유 주소용, 기본값 id |
| title | 문자열, 최대 120자 | 공개할 때 필수 |
| summary | 문자열, 최대 300자 | 공개할 때 필수 |
| genre | 문자열 최대 80자 또는 null | 선택 |
| status | draft 또는 published | 새 작품은 draft |
| role | 문자열 최대 120자 또는 null | 선택, 팀장과 개발 담당 구분 |
| period.start | YYYY-MM 또는 null | 미확인 시 null |
| period.end | YYYY-MM 또는 null | 시작보다 빠를 수 없음 |
| period.ongoing | boolean | true이면 종료 월은 null |
| platforms | 중복 없는 문자열 목록, 항목당 60자 | 확인된 플랫폼만 입력 |
| technologies | 중복 없는 문자열 목록, 항목당 80자 | 확인된 기술만 입력 |
| teamSize | 1 이상의 정수 또는 null | 미확인 시 null |

작품 ID와 slug는 묶음 안에서 각각 고유해야 한다. 제목을 수정해도 ID와 주소는 자동으로 바꾸지 않는다. 첫 버전의 편집기는 생성한 slug를 유지하며 주소 변경 기능은 제공하지 않는다.

초안은 이름과 소개가 비어 있어도 저장할 수 있다. 공개 대상으로 선택한 작품은 제목과 요약의 필수 검증을 통과해야 내보낼 수 있다. 역할, 영상과 그래프 자료가 없다는 이유만으로 작품 전체의 공개를 막지 않는다.

## 작품 미디어와 개발 기록

| 필드 | 내용 |
| --- | --- |
| media.coverAssetId | 대표 이미지 ID 또는 null |
| media.screenshotAssetIds | 중복 없는 이미지 ID 목록 |
| media.video | YouTube 정보 또는 null |
| contribution.responsibilities | 직접 및 공동 구현한 역할 목록, 항목당 2000자 |
| contribution.leadership | 협업과 의사결정 사례 목록, 항목당 2000자 |
| overview | 게임 소개, 최대 20000자 |
| caseStudies | 문제 해결 사례 목록 |
| outcome | 확인한 결과, 최대 20000자 |
| reflection | 배운 점과 개선 방향, 최대 20000자 |
| links | 코드, 문서와 빌드 링크 |

사례는 `id`, `title`, `problem`, `alternatives`, `solution`, `outcome`, `evidence`로 구성한다. 사례 ID는 해당 작품 안에서 고유해야 한다. 공개할 사례에는 제목, 문제, 해결과 결과가 필요하다. 작성 중인 사례를 남긴 채 공개를 진행하려면 먼저 완성하거나 공개 콘텐츠에서 제외하도록 편집한다.

근거 링크는 라벨과 HTTPS 주소로 저장한다. 첫 버전의 공개 링크 필드는 일반 웹 링크이며 별도의 이메일 주소 형식은 추가하지 않는다. 링크가 가리키는 자료의 실제 접근 가능 여부는 공개 전 수동 미리보기로 확인한다.

### YouTube 주소 정리

사용자는 영상 URL을 입력하고, 저장 자료에는 `provider: youtube`, `videoId`, `title`만 남긴다. 현재 형식은 11자리 영문, 숫자, 밑줄과 하이픈의 ID를 사용한다. 이것은 연결 가능한 주소를 만드는 형식 검사이며 실제 존재나 임베드 가능 여부의 확인이 아니다.

주소 정리기는 HTTPS의 `youtube.com/watch?v=...`, `www.youtube.com/watch?v=...`, `youtu.be/...`, `youtube.com/shorts/...`, `youtube.com/embed/...` 및 해당 www와 m 호스트를 지원하는 방향으로 정의한다. 호스트는 정확하게 비교하며, 경로와 v 매개변수에서 ID를 추출한다. 불필요한 공유 추적 매개변수는 저장하지 않는다.

재생목록, 라이브 주소와 시작 시간 입력은 첫 버전 범위에서 제외한다. 지원하지 않는 주소는 영상 ID를 직접 입력하거나 지원 형식의 링크를 붙여넣도록 안내한다. 실제 재생 검증은 플레이어 미리보기에서 수행한다.

## 아키텍처

작품당 그래프 하나를 둔다. `projectId`는 해당 작품을 연결하며 별도의 작품 내 그래프 ID는 만들지 않는다. 그래프를 추가하지 않은 작품은 아키텍처 준비 중으로 표시할 수 있다.

| 필드 | 의미 |
| --- | --- |
| projectId | 존재하는 작품 ID |
| verified | 전시장 주인이 실제 구조로 확인했는가 |
| revision.label | 구조 기준 버전이나 설명 또는 null |
| revision.reviewedAt | 확인 날짜 YYYY-MM-DD 또는 null |
| revision.sources | 코드, 문서 또는 작성자 확인 근거 |
| groups | 시스템 그룹과 3D 배치 층 |
| nodes | 시스템 설명과 개인 기여 |
| edges | 시스템 사이의 관계 |

공개 그래프에는 최소 한 노드, 구조 확인 날짜와 최소 한 근거가 필요하다. `verified`는 자료 작성자의 확인 표시이며 코드 분석이나 사실 검증을 자동 수행했다는 뜻이 아니다. 미확인 그래프는 전체 초안에는 유지하고 공개 출력에서는 제외해 준비 중 상태로 둔다.

### 그룹과 노드

그룹은 `id`, `label`, `layer`로 구성한다. layer는 0~20의 정수이며 공간의 그룹 배치에 사용한다. 자유로운 카메라 좌표나 개인 관람 시점은 구조 자료로 저장하지 않는다.

| 노드 필드 | 기준 |
| --- | --- |
| id | 해당 그래프 안에서 고유 |
| label | 최대 80자, 공개할 때 필수 |
| groupId | 해당 그래프의 그룹 ID 또는 null |
| parentId | 상위 노드 ID 또는 null |
| responsibility | 시스템 책임, 최대 4000자, 공개할 때 필수 |
| inputs와 outputs | 항목당 최대 500자의 목록 |
| decisions | 설계 이유, 최대 4000자 |
| contributionType | direct, shared, team 또는 unknown |
| contributionNote | 개인 기여 설명, 최대 2000자 |
| relatedCaseIds | 같은 작품의 사례 ID 목록 |
| codeRefs | 관련 코드의 라벨과 URL |

`direct`와 `shared`는 담당 시스템 강조 대상이다. 공개할 때 해당 기여 설명이 필요하다. `unknown`은 미확인을 뜻하며 팀장이라는 역할로 다른 값으로 자동 변환하지 않는다. 상하위 노드는 중첩 구조이며 자기 자신을 부모로 지정하거나 부모 관계의 순환을 만들 수 없다.

### 연결선

| 필드 | 기준 |
| --- | --- |
| id | 해당 그래프 안에서 고유 |
| source | 출발 노드 ID |
| target | 도착 노드 ID |
| type | call, data, event 또는 dependency |
| label | 최대 80자, 공개할 때 필수 |
| description | 관계의 설명, 최대 2000자 |

call은 source가 target을 호출한다는 뜻이다. data는 source에서 target으로 자료가 전달됨을 뜻한다. event는 source에서 전달한 이벤트를 target이 받는 관계다. dependency는 source가 target에 의존함을 뜻한다. 범례와 설명에서도 이 방향을 유지한다.

전체 연결 그래프에는 순환이 있을 수 있다. 시스템 상하위 관계의 순환과 일반 연결선의 순환을 구분한다. 자기 자신으로 연결한 선은 설명을 확인하도록 주의 메시지를 표시하며, 재귀나 내부 반복을 실제로 설명하는 관계라면 허용한다.

## 이미지 자산

자산 데이터는 ID, 경로, 형식, 크기, 가로와 세로 픽셀, 대체 설명을 저장한다. 이미지의 실제 바이트는 JSON에 base64로 넣지 않고 파일로 보관한다.

| 필드 | 기준 |
| --- | --- |
| id | 묶음 안에서 고유 |
| path | assets 아래의 정해진 파일명 형식 |
| mimeType | PNG, JPEG, WebP 또는 AVIF의 MIME |
| byteSize | 실제 바이트 수, 파일당 최대 10MiB |
| width와 height | 실제 이미지의 양의 정수 크기 |
| alt | 최대 300자, 공백만 있는 값 불가 |

내보내기 파일명은 자산 ID를 기준으로 생성한다. 경로는 영문 소문자, 숫자와 하이픈의 파일명 및 지원 확장자로 제한한다. 외부 URL, 절대 경로와 부모 디렉터리 경로를 자산 경로로 저장하지 않는다. 선택한 원본의 한글 파일명은 내보내기 과정에서 정해진 이름으로 변환한다.

자산 ID, 저장 경로와 실제 파일명 및 MIME이 일치해야 한다. 파일을 읽어 이미지가 정상적으로 해석되는지와 메타데이터가 실제 값과 맞는지 확인한다. 확장자만으로 형식을 판단하지 않는다. 이미지 하나를 여러 화면에서 사용하면 같은 자산 ID를 참조한다.

10MiB는 초안 입력의 파일별 한도다. 실제 공개 전시실의 총 자원량 목표와는 별도로 관리하며, 공개 미리보기에서 큰 이미지의 최적화를 안내한다.

## 검증 계층

검사는 입력 중, 표준 자료 저장, 공개 내보내기와 관람 시점에 나눠 수행한다. 사용자 오류를 발견해도 기존 데이터를 임의로 삭제하지 않는다.

| 계층 | 검사 | 실패 시 동작 |
| --- | --- | --- |
| 입력 중 | 필수값, 길이, 주소 정리 | 해당 필드 안내, 입력 유지 |
| 형식 검사 | JSON 구문, 버전, 키, 타입과 enum | 표준 자료 반영 중단 |
| 관계 검사 | ID 중복, 작품 순서와 연결 참조 | 해당 작품 또는 시스템으로 이동 |
| 파일 검사 | 파일 존재, 형식과 이미지 정보 | 내보내기 중단, 자산 수정 안내 |
| 공개 검사 | 프로필, 작품 필수값, 그래프 확인과 기여 | 수정하거나 해당 자료 제외 |
| 관람 방어 | 예상치 못한 파일 실패와 누락 | 가능한 콘텐츠 유지, 복구 안내 |

관람 화면의 방어 처리는 잘못된 공개 내보내기를 허용한다는 뜻이 아니다. 내보내기는 구조와 참조 검증을 통과한 파일만 생성한다.

### 별도 관계 검증 목록

다음 규칙은 JSON Schema만으로 충족하지 않으므로 실제 검증 함수에서 구현해야 한다.

| 규칙 | 검사 |
| --- | --- |
| R01 | 작품 ID와 slug가 각각 고유하다 |
| R02 | projectOrder가 모든 작품 ID를 정확히 한 번 포함한다 |
| R03 | 그래프 projectId가 존재하며 작품당 그래프는 최대 하나다 |
| R04 | 그룹, 노드, 연결선 ID가 각 목록 안에서 고유하다 |
| R05 | 노드 groupId와 parentId가 해당 그래프 안에 존재한다 |
| R06 | 부모 관계에 자기 참조와 순환이 없다 |
| R07 | 연결선 source와 target이 같은 그래프 안에 존재한다 |
| R08 | 사례 ID는 작품 안에서 고유하고 relatedCaseIds가 존재한다 |
| R09 | 모든 미디어 및 프로필 자산 참조가 존재한다 |
| R10 | 자산 ID와 경로는 각각 고유하고 실제 파일과 일치한다 |
| R11 | 시작과 종료 월의 순서 및 진행 중 표시가 일치한다 |
| R12 | 외부 링크는 유효한 HTTPS URL이며 호스트가 존재하고 인증정보가 없다 |
| R13 | 공개 노드의 직접 및 공동 구현에는 기여 설명이 있다 |
| R14 | 코드와 문서 근거에는 URL이 있고 작성자 근거에는 확인 설명이 있다 |
| R15 | 공개 자료는 공개 작품, 확인한 그래프와 도달 가능한 자산만 포함한다 |

오류는 code, path, message와 이동 대상으로 반환한다. 예를 들어 `R07`의 path가 `/architectures/0/edges/1/target`이면 해당 작품의 연결선 편집 화면으로 이동한다. 사용자는 오류 코드보다 시스템 이름과 수정할 항목을 먼저 읽는다.

### 오류와 주의 메시지

필수값 누락, 존재하지 않는 참조와 파일 불일치는 내보내기를 막는 오류다. 영상 미등록, 그래프 미등록과 미확인 플랫폼 등은 선택 자료에 대한 안내다. 0개의 공개 작품은 빈 전시장으로 내보낼 수 있지만 확인 안내를 표시한다.

자기 참조 연결선과 실제 성과의 근거 누락 등은 검토가 필요한 주의 항목으로 표시한다. 검증기에서 링크의 실제 접근 권한이나 프로젝트 성과의 진실성을 자동 확인했다고 표현하지 않는다.

## 초안 저장과 가져오기

이름이나 요약이 비어 있어도 workspace 형식의 데이터는 저장할 수 있다. 잘못된 영상 주소 등 표준 자료로 변환할 수 없는 입력은 마지막으로 유효했던 값과 분리해 편집 상태로 저장한다.

브라우저 초안과 전체 백업의 `backup.json`에는 다음 편집 메타데이터를 기록한다. portfolio.json 외에 [backup 메타데이터 스키마](../spec/schemas/backup.schema.json)와 [export-manifest 스키마](../spec/schemas/export-manifest.schema.json)를 구현했다.

| 필드 | 형식과 의미 |
| --- | --- |
| backupVersion | 현재 값 1.0.0 |
| savedAt | 저장·백업 대상 스냅샷의 UTC 시각, ISO 8601의 Z 표기; 저장 성공은 transaction 완료 뒤 별도 표시 |
| editorState.screen | profile, projects, presentation 또는 export |
| editorState.projectId | 편집 중인 작품 ID 또는 null |
| pendingInputs | 정리되지 않은 입력 원문 목록 |

pendingInputs의 항목은 scope, projectId, entityId, path와 rawValue로 구성한다. scope는 site, project, graph, group, node 또는 edge다. projectId는 작품과 그래프에 대한 대상 작품을 지정하고, entityId는 그룹과 노드 및 연결선 대상을 지정한다. path는 해당 대상 객체 안의 필드 경로이고 rawValue는 입력한 원문 문자열이다.

예를 들어 아직 정리할 수 없는 영상 주소는 scope가 project, projectId가 해당 작품 ID, entityId가 null, path가 `/media/video`인 항목으로 보관한다. 작품 배열의 순번을 대상 주소로 사용하지 않아 순서를 바꿔도 다른 작품에 입력이 붙지 않도록 한다. 가져온 pendingInputs는 먼저 해당 화면의 입력으로 복원하고 공개 출력에 넣지 않는다. 대상 작품이나 시스템이 없으면 임의로 다른 항목에 적용하지 않고 복구할 수 없는 입력으로 안내한다.

초안 저장 버튼은 표준 자료와 입력 상태 및 자산 바이트를 함께 저장한다. 큰 이미지 자산은 IndexedDB 등 구조화된 브라우저 저장소를 사용하는 방향으로 검토한다. 저장 요청 성공을 확인한 뒤 저장 완료 표시를 하고, 실패하면 현재 입력과 자산을 유지하며 백업 내보내기를 제안한다.

가져오기는 첫 버전에서 전체 교체 방식으로 정한다. 기존 자료와 새 자료를 임의로 병합하지 않는다. 다음 순서를 거친다.

1. 패키지를 별도 임시 상태에서 읽고 형식과 지원 버전을 검사한다.
2. 작품과 이미지의 관계를 확인한다.
3. 가져올 프로필, 작품 수와 자료 종류를 미리 보여준다.
4. 현재 초안을 백업할 수 있는 동작과 교체 확인을 제공한다.
5. 확인 후 자료와 자산을 한 작업으로 교체한다.
6. 교체 실패 시 이전 초안으로 복귀한다.

일반 JSON 파일에 자산 목록이 있으면 해당 이미지 파일도 함께 받는다. 파일 없는 자산 참조를 성공으로 처리하지 않는다. 예시 자료는 예시 작업 공간으로 표시하며 공개 자료로 자동 변환하지 않는다.

## 공개 내보내기

공개 변환은 원본 workspace를 직접 변경하지 않고 별도 복사본에서 수행한다.

1. 프로필과 공개 작품의 필수값을 검사한다.
2. published 작품만 선택하고 기존 순서를 유지한다.
3. 선택 작품의 verified 그래프만 남긴다.
4. 남긴 그래프의 형식, 근거와 연결을 검사한다.
5. 프로필, 테마와 선택 작품에서 참조한 이미지 ID를 모은다.
6. 해당 자산과 실제 파일을 포함하고 사용하지 않는 자산은 제외한다.
7. projectOrder를 공개 작품 ID만으로 구성하고 kind를 public으로 바꾼다.
8. 결과를 public 형식과 관계 규칙으로 다시 검사한다.
9. 내용 파일, 이미지와 export-manifest.json을 패키지로 생성한다.

미확인 그래프가 있으면 원본에는 남기고 공개 패키지에서는 제외했다는 안내를 제공한다. 확인한 그래프 안에 오류가 있으면 수정 전 내보내기를 막는다. 같은 기준으로 잘못된 공개 대상 사례도 수정하도록 안내한다.

export-manifest.json에는 exportVersion, schemaVersion, kind, 생성 시각과 경로 및 바이트 수의 파일 목록을 기록한다. 첫 버전은 public-content와 workspace-backup을 구분한다. 공개 패키지는 한 번 더 정상적으로 읽을 수 있는지 확인한 뒤 다운로드 완료를 표시한다.

내보내기 실패가 원본의 공개 상태, 이름과 작품 내용을 바꾸면 안 된다. 실제 사이트 게시 여부는 내보내기 결과와 별도로 안내한다.

## 버전과 업데이트

템플릿 실행 코드의 버전과 자료 schemaVersion을 분리한다. 현재 검증기는 `1.0.0`만 지원하는 기준으로 작성한다. 다른 버전을 받으면 지원하지 않는 버전이라고 안내하고 원본을 유지한다.

새 버전은 이름이 비슷하다는 이유로 자동 적용하지 않는다. 필요한 자료 변환 함수를 추가하고 원본 백업, 변환 결과 검사와 적용 확인을 거친다. 알 수 없는 필드나 개인 콘텐츠를 조용히 삭제하는 하위 버전 변환은 수행하지 않는다.

아직 이전 정식 버전이 없으므로 실제 마이그레이션 함수는 이번 단계에서 만들지 않는다. 향후 업데이트는 기존 이름, 작품 ID, slug, 순서와 자산 참조가 유지되는지 확인해야 한다.

## 명세 검증과 구현 범위

현재 검사 결과는 [데이터 명세 검증 기록](../spec/verification.md)에 기록했다. 스키마 표준 검사와 예시 및 경계 검사 26개를 통과했다.

스키마 자체의 표준 적합성과 세 예시의 형식, 공개 자료의 빈 이름, 잘못된 영상 ID, 지원하지 않는 버전 등의 경계 입력을 검사한다. 별도 관계 규칙은 TypeScript 검증기에 구현했다. R10의 실제 이미지 바이트·디코딩·크기 검사와 파일 패키지 검증도 구현했다. 실제 관람과 작품 편집기의 연결 및 GitHub 배포는 남아 있다.

빈 전시장 예시는 친구에게 제공할 기본값이다. 첫 개인 전시장 예시는 확인된 세 작품을 초안으로 등록하며 개인 이름, 제작 기술과 실제 코드 구조를 임의로 채우지 않는다. 아키텍처 예시는 kind가 example이고 verified가 false이며 실제 작품으로 공개할 수 없다.

## 저장·패키지 구현에서 확정한 규칙

workspace-backup과 public-content ZIP 모두 export-manifest.json을 포함한다. manifest의 files는 자기 자신을 제외한 정확한 파일 목록과 바이트 수를 적는다. 실제 파일과 목록이 다르거나 쓰지 않는 추가 파일이 있으면 가져오기를 중단한다.

공개 content/site.json은 schemaVersion, kind(public)와 site를 가진 객체다. content/projects.json과 content/assets.json은 배열이며, 그래프 파일은 작품 ID별 architecture 객체다. 공개 ZIP을 가져오면 published 상태는 유지하면서 로컬 workspace로 편집을 시작한다. 기획 예시 백업은 example 종류를 유지한다.

공개 대상 필드에 아직 정리하지 못한 입력 원문이 있으면 공개 ZIP 생성을 막는다. 제외한 초안이나 미확인 그래프의 원문은 전체 백업에 보존한다. 대상이 사라진 원문은 안내하며 다른 필드에 적용하지 않는다.

ZIP은 최대 64MiB, 압축 전 합계 128MiB와 최대 512개 파일을 지원한다. JSON은 파일별 2MiB이며 이미지 입력 한도는 기존의 10MiB다. 지원하는 일반 단일 ZIP은 저장과 deflate 압축을 사용한다. [저장과 패키지 사용 안내](./storage-and-packages.md)


## 편집기 입력과 삭제 계약 — 2026-10-07

일반 필드는 형식·관계 검사 후에만 표준 자료를 갱신한다. 실패한 원문은 기존 backup 1.0.0의 대상 범위·작품 ID·시스템/연결 ID·경로로 보관한다. 작품 순서 이동은 원문 소속을 바꾸지 않는다. 개발 사례의 배열 항목을 삭제하면 그 사례 원문을 제거하고 뒤 항목 경로를 정리하며 잘못된 인덱스는 자동 보정하지 않는다. 과거 대상이 없는 사례 원문은 새 사례 추가 전 unresolvedCaseStudies 경로로 보존해 새 사례에 붙이지 않고, 편집 화면의 미정리 입력 목록과 백업에 남긴다. 공개 대상에 이 원문이 남으면 내보내기가 차단된다.

작품 삭제는 해당 그래프·개발 사례·관련 원문과 전시 순서를 정리한다. 그룹 삭제는 시스템의 그룹 참조만 해제한다. 시스템 삭제는 연결·자식 부모 참조와 해당 입력 원문을 함께 정리한다. 개발 사례 삭제는 시스템의 사례 참조도 정리한다. 이미지 연결 해제는 파일 삭제가 아니다. 실제 파일은 전체 백업에 남으며 공개 선별 단계에서 사용하지 않는 파일을 제외한다.

구조를 수정하면 verified를 해제하며 작성자가 명시적으로 확인할 수 있다. 구조 공개에 필요한 확인일·근거·시스템 설명·기여 설명은 공개 내보내기에서 다시 검사한다. 직전 삭제 되돌리기는 현재 세션의 한 단계 기록이며 다른 콘텐츠 편집이나 새로고침 후에는 제공하지 않는다.


## 아키텍처 관람 상태 — 2026-10-07

배치와 프레임은 자료를 수정하지 않는다. 2D 위치는 그룹/부모와 ID에 따라 계산하고 3D 높이는 그룹 layer에 기반한다. 부모 관계는 별도 점선으로 표시하며 일반 연결의 순환·자기 연결·평행 연결을 트리로 바꾸지 않는다. 관계 종류·화살표·라벨과 설명을 함께 제공한다.

선택은 노드 ID로 공유하며 해당 ID가 없어지면 선택을 비운다. 강조는 direct/shared만 포함하며 팀 전체 구현을 개인 구현으로 자동 분류하지 않는다. 공개와 작업 공간은 별도의 관람 세션 키를 사용한다. 카메라·2D 확대·선택·현재 보기와 강조는 세션 메모리 값이며 공개 자료나 백업 필드를 추가하지 않는다.

기획 예시와 미확인 초안은 명시적으로 표시한다. 실제 구조가 없는 작품에는 예시를 대입하지 않는다. 3D 실패는 자료나 선택을 변경하지 않고 2D·시스템 목록으로 복귀한다.


## 전시장 관람 상태 — 2026-10-10

전시실과 패널 배치는 공통 조회 순서에서 파생하며 portfolio schema를 추가하지 않는다. 방당 최대 6작품이며 카메라·전시실·선택·이동 지점·수동 동작 줄이기 설정은 출처와 관람 모드별 세션 메모리다. 카메라는 위치와 target을 실제 관측한 숫자로 유지하며 콘텐츠/백업 ZIP에 들어가지 않는다.

작품 순서 변경으로 선택 작품의 방이 바뀌면 새 방을 찾아 기존 시점을 버린다. 작품이 없어지면 선택을 비우고 이동 지점을 로비로 정리한다. 비활성 문서에서는 프레임을 멈추고 복귀 시 큰 시간 간격을 그대로 이동에 적용하지 않는다. 실제 이미지는 asset ID로 조회하고 현재 방에서만 읽는다. 표지 실패는 기본 이름 표지로 남기며 게임 이미지나 성과를 추정하지 않는다.


## 저장 안전성과 관람 상태 복원

2026-10-10 개선에서 portfolio와 파일 버전 1.0.0은 유지했다. 로컬 저장 레코드의 commitId와 session.storageToken은 낙관적 저장 충돌 검사에만 사용하며 portfolio.json, backup.json과 공개 패키지의 필드는 아니다. 일반 저장과 명시적인 파일 교체는 현재 저장본과의 비교를 통과해야 한다. 읽기 실패 상태는 새 빈 초안으로 자동 저장하지 않는다.

그래프 시점과 2D viewBox는 화면 왕복 직전에 읽은 최신 ref로 저장한다. 자식 조작 직후 부모가 다시 렌더되지 않아도 최신 값을 복원한다. 이미지 10MiB/4천만 픽셀 한도는 브라우저와 Node 빌드의 공통 정책이다.
