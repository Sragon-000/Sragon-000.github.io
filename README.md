# IO — 게임공학 프로젝트 전시장

친구가 복제해 자기 이름으로 운영할 수 있는 GitHub Pages 전시장 플랫폼입니다. **초안 편집·저장, 갤러리·상세, 2D·3D 아키텍처와 3D 전시장**을 구현했습니다. 설정 주소에서 이름과 전시장 이름, 프로필 이미지를 입력하고 이 기기에 저장할 수 있습니다. 전체 백업과 공개 콘텐츠 ZIP을 생성하고 검증 후 가져올 수 있습니다. 공개 파일을 읽는 갤러리·상세와 초안 스냅샷 미리보기, YouTube 주소 입력과 지연 재생을 연결했습니다. 기본 정보·작품·이미지·개발 사례·시스템/연결 목록 편집과 전시 설정을 구현했습니다. 2D·3D 그래프 탐색도 연결했습니다. 3D 전시장도 연결했습니다. 빈 템플릿, 공개 콘텐츠 반영·빌드 검사와 GitHub Pages 워크플로도 준비했습니다. 실제 GitHub 배포는 저장소 연결 후 확인합니다.

## 실행

Node 20.19 이상인 20.x 또는 Node 22.12 이상을 사용합니다. 이번 검증 환경은 Node 22.23.2입니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 엽니다. 개발 환경의 화면 하단 **개발 검증 도구**에서는 기존 JSON 예시를 선택하거나 입력해 형식·관계 및 공개 선별을 확인할 수 있습니다. **기획 예시 그래프 미리보기**로 실제 작품과 구분된 렌더링 예시를 볼 수 있습니다. 이는 실제 편집기가 아니며, 입력은 메모리에서만 유지됩니다. 공개 빌드에는 이 도구와 개인 예시 자료가 포함되지 않습니다.

## 확인과 빌드

```sh
npm test
npm run build
npm run preview
```

자동 검사 211개와 Chromium 브라우저 회귀 검사 21개, TypeScript 검사 및 빌드를 통과했습니다. 실제 브라우저 저장과 새로고침 복원, 이미지 포함 ZIP 다운로드·재가져오기와 공개 자료 선별을 확인했습니다. 공개 하위 경로의 상세 직접 접근과 새로고침, 미리보기의 공개·초안 구분, 공식 예제 영상 재생과 화면 이동 시 정리를 확인했습니다. 실제 프로젝트 영상과 GitHub 배포는 아직 검증하지 않았습니다.

build는 site-content의 공개 자료와 실제 이미지를 검증하고 앱과 콘텐츠를 dist에 생성한 뒤 출력 파일과 HTML 경로·공유 메타데이터·JPEG 카드를 검사하고 초기 JS 크기 예산도 확인합니다. 브라우저의 초안과 백업은 자동으로 복사하지 않습니다. 기본 템플릿에는 중립적인 제작자·전시장 이름과 빈 작품 목록만 포함합니다.

저장소 하위 경로용 앱 빌드는 다음과 같이 설정할 수 있습니다.

```sh
PAGES_BASE=/Project_IO/ npm run build
```

루트 `/`와 `/Project_IO/` 빌드를 확인했고 하위 경로의 설정 주소 직접 접근 및 새로고침을 브라우저에서 확인했습니다. 프로필 이름으로 배포 경로를 계산하지 않습니다. 공유용 절대 주소를 로컬에서 검사하려면 PAGES_URL에 실제 HTTPS 사이트 주소를 함께 지정합니다. Actions는 Pages의 base_url을 자동으로 사용합니다.

## 코드 확인과 정리

```sh
npm run check
npm run format
```

check는 Prettier 형식 검사, Oxlint와 TypeScript 검사를 순서대로 수행합니다. CI에서도 테스트 전에 실행합니다. 화면·저장·도메인 사이의 가져오기 경계와 기본 Hook 순서·의존성을 검사합니다. 현재 Three.js와 DOM을 연결하는 코드에는 React Compiler를 적용하지 않으며 관련 진단의 범위는 [기술 기록](./docs/technical-plan.md)에 설명했습니다.

format은 코드·스타일·테스트·설정·명세 Schema를 정리합니다. 공개 site-content와 manifest, 개인 자료와 예시·vendor 파일은 수정 대상에서 제외합니다.

## 브라우저 회귀 검사

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright 1.64.0이 사용자 브라우저와 분리된 Chromium과 임시 테스트 프로필을 사용합니다. 5290·5291 포트는 검사가 관리하며 기존 서버를 재사용하지 않습니다. 두 탭 충돌·복구 확인, 읽기 실패 보호와 다시 읽기, 2D·3D 그래프의 시점 복원, 이미지·미정리 입력을 포함한 ZIP 왕복, 루트/하위 경로와 설정 화면 왕복을 검사합니다. 임시 공개 자료로 프로덕션 루트/하위 경로 빌드, JavaScript 없는 공유 HTML, 공유 주소→상세/새로고침·링크 복사, 초기 지연 요청과 다운로드 실패 복귀도 확인합니다. CI도 같은 검사를 배포 전에 수행합니다. 보고서는 playwright-report에 생성하며 기획 예시와 개발용 시점 출력은 공개 빌드에 포함되지 않습니다.

## 친구에게 나누고 배포하기

자세한 절차는 [전시장 복제와 GitHub Pages 배포](./docs/github-pages-guide.md)를 따릅니다. 공개 콘텐츠 ZIP을 자기 저장소의 로컬 폴더에 반영합니다.

```sh
npm run content:import -- "/경로/공개콘텐츠.zip" --check
npm run content:import -- "/경로/공개콘텐츠.zip"
npm run build
npm run preview
```

정상 반영 시 이전 공개 파일은 별도 폴더에 보존됩니다. 실행 중인 개발 서버는 재시작하세요. 확인한 `site-content/` 변경을 기본 브랜치에 올리고, 저장소 Settings → Pages → Source를 **GitHub Actions**로 선택합니다. 제공된 워크플로가 검사 후 dist만 배포하며 실제 경로는 Pages 메타데이터로 정합니다. 다른 브랜치와 pull request는 빌드만 검사합니다.

친구에게는 개인화하기 전의 빈 템플릿 저장소를 제공합니다. 템플릿 기본 자료를 개인 콘텐츠 위에 덮어쓰지 않는 업데이트 절차도 안내에 포함했습니다. 현재 폴더는 실제 GitHub 저장소에 연결되어 있지 않습니다.

## 공통 데이터 기능

- `src/domain/create.ts`: 빈 workspace와 제목에 의존하지 않는 작품 ID 생성
- `src/domain/validate.ts`: Ajv Draft 2020-12, 날짜·URI, R01–R15 관계 검사와 오류 이동 대상
- `src/domain/public.ts`: 원본을 보존하는 공개 작품·확인 그래프·사용 자산 선별
- `src/domain/select.ts`: 관람 모드와 순서를 적용하는 공통 조회
- `src/app/router.ts`: 관람 및 설정 해시 주소

R10의 자산 ID·경로·MIME 메타데이터와 실제 이미지 바이트·디코딩·픽셀 크기를 검사합니다. URL 검사는 형식 검사이며 실제 접속 가능 여부를 확인하지 않습니다.

## 작품 편집

`#/studio/profile`에서 제작자 소개와 공개 링크를 작성하고, `#/studio/projects`에서 **작품 추가**를 선택합니다.

- 작품 개요, 제작 정보, 이미지·영상, 개인 기여, 개발 사례와 결과·회고를 입력합니다. 작품명·요약은 공개할 때 필수입니다.
- 이미지 대체 설명을 먼저 적고 파일을 선택합니다. 연결 해제·교체 전 파일은 전체 백업에 보관되고 공개 ZIP에는 사용한 이미지만 포함됩니다.
- **공개 대상으로 선택**한 작품만 공개 미리보기와 공개 ZIP에 포함됩니다. 아직 게시된 상태를 뜻하지 않습니다.
- 목록의 위로·아래로 버튼으로 전시 순서를 바꿉니다. 이름과 순서 변경 후에도 작품 ID와 입력 원문 연결을 유지합니다.
- 삭제 화면에서 작품명과 정리 범위를 확인합니다. 직전 삭제는 바로 되돌릴 수 있으며 다른 내용을 편집하거나 새로고침하면 되돌리기가 종료됩니다.
- 아키텍처는 그룹·시스템·연결 목록으로 입력합니다. 시스템 삭제 시 연결과 부모 참조를 정리하고, 구조 수정 후에는 확인 상태를 해제합니다. 입력한 구조는 작품 상세의 2D·3D 그래프에서 탐색할 수 있습니다.

`#/studio/presentation`에서 전시장 설명, 첫 관람 화면, 테마·로고·브라우저 아이콘을 설정합니다. 라이트 테마는 미리보기에서 확인할 수 있습니다. 3D 공간은 같은 작품 순서와 공개 선택을 사용합니다.

입력 오류는 원문과 마지막 유효 값을 분리해 보관합니다. **보관된 미정리 입력**에서 대상이 없는 과거 입력도 확인하고 원문을 제거할 수 있습니다. 잘못된 사례 원문이 삭제 후 다른 사례나 새 사례에 연결되지 않게 정리합니다. 미리보기에는 마지막 유효 자료를 표시하고, 공개 대상의 미정리 입력은 내보내기를 차단합니다.

상단 고정 도구에서 저장과 미리보기를 실행할 수 있습니다. 일반 화면 이동과 미리보기 복귀는 값을 유지하며, 새로고침은 마지막 저장본을 불러옵니다. 저장하지 않은 상태로 브라우저를 떠날 때는 브라우저의 기본 확인을 요청합니다.

## 초안 저장과 파일 이동

`#/studio/profile` 또는 `#/studio/export`에서 **초안 보관과 파일 이동**을 사용합니다.

1. 이름, 전시장 이름과 프로필 이미지를 입력합니다.
2. **이 기기에 초안 저장**을 누르면 데이터·입력 원문·이미지가 함께 저장됩니다.
3. **전체 초안 백업** 또는 **공개 콘텐츠 내보내기**로 ZIP을 생성한 후 표시되는 다운로드 링크를 선택합니다.
4. **백업 또는 콘텐츠 가져오기**에서 ZIP 또는 JSON과 이미지를 선택합니다.
5. 검사 후 제작자·작품·이미지 수를 확인하고, 필요하면 현재 초안을 백업한 다음 교체합니다. 취소와 실패 시 현재 초안을 유지합니다.

초안은 현재 브라우저의 배포 경로에 묶여 있습니다. 다른 브라우저나 실제 GitHub Pages 주소로 옮길 때는 백업 파일로 이동합니다. 공개 ZIP은 저장소에 반영할 콘텐츠이며 파일 다운로드만으로 사이트가 게시되지는 않습니다. [저장과 패키지 사용 안내](./docs/storage-and-packages.md)

## 갤러리·상세와 영상

설정 화면에서 **공개 대상 미리보기** 또는 **초안 포함 전체 미리보기**를 선택합니다. 현재 유효 자료의 읽기 전용 스냅샷을 표시하며 종료 후 입력은 유지됩니다. 새로고침하면 미리보기는 종료되고 배포된 공개 파일을 읽습니다.

작품 편집 화면의 **YouTube 영상**에서 URL 또는 ID를 입력할 수 있습니다. 잘못된 주소는 원문으로 보존하고 마지막 유효 영상을 유지합니다. 미리보기는 입력 원문 대신 유효 자료를 보여주므로 공개 내보내기에서 미정리 오류를 별도로 해결해야 합니다.

공개 사이트는 base 경로의 export-manifest.json, content/site.json·projects.json·assets.json을 읽습니다. 구조 파일은 해당 작품 상세에서 읽고 이미지는 표시할 때 로드합니다. 콘텐츠가 없으면 빈 전시장을, 파일이 잘못되면 오류와 재시도를 제공합니다. 공개 ZIP을 앱의 public 폴더에 풀면 다음 빌드에 포함할 수 있지만, 현재 저장소에는 테스트 콘텐츠를 넣지 않았습니다. 실제 배포는 별도입니다.

YouTube는 재생 선택 후 API와 플레이어를 불러옵니다. 이전·다음 작품, 그래프 확대 또는 미리보기 종료 시 플레이어를 정리합니다. 실제 플레이 영상 주소는 아직 제공되지 않았습니다. 검증에 사용한 Google 공식 예제 영상은 테스트 폴더에만 있습니다.

## 아키텍처 둘러보기

작품 상세의 시스템 아키텍처에서 **2D 보기**, **3D 보기**와 **그래프 크게 보기**를 사용합니다. 시스템을 선택하면 책임·입출력·설계 결정·개인 기여·연결 이유와 개발 사례·코드 링크를 읽습니다. 두 보기와 상세·확대 화면에서 선택과 담당 강조를 유지합니다. 없는 시스템의 선택은 비웁니다.

2D는 확대·축소·이동 버튼과 PC의 빈 공간 드래그를 지원합니다. 그래프의 시스템에 키보드로 접근해 Enter 또는 Space로 선택할 수 있습니다. 3D는 드래그 회전·휠/두 손가락 확대를 지원합니다. 두 보기 모두 시스템 목록과 설명으로 이동 버튼을 제공합니다. **내 담당 강조**는 직접·공동 구현을 표시합니다.

3D는 선택할 때만 Three.js를 불러오며, 보기 종료 때 장면·입력·프레임과 WebGL 자원을 정리합니다. 3D를 열 수 없거나 연결이 끊기면 선택을 유지한 2D와 시스템 목록으로 돌아갑니다. 다시 시도하거나 2D에서 계속 관람할 수 있습니다. 카메라와 확대 상태는 현재 페이지의 메모리에만 남으며 콘텐츠 ZIP에 포함하지 않습니다.

구조가 없는 작품은 준비 상태를 표시합니다. 공개 관람은 제작자가 확인한 그래프만 표시하고, 초안 포함 미리보기는 작성 중인 구조도 표시합니다. 기획 예시를 실제 작품 구조로 자동 등록하지 않습니다. 실제 게임의 확인 자료는 아직 제공되지 않았습니다.

Three.js 0.180.0과 @types/three 0.180.0을 고정했습니다. npm 패키지를 사용하며 준비용 vendor 파일은 빌드에 넣지 않습니다. [Three.js 라이선스](./public/licenses/three.txt)를 빌드에 포함합니다.

## 3D 전시장 관람

갤러리 또는 메뉴에서 **3D 전시장**을 엽니다. 같은 자료의 작품 순서로 방당 최대 6개 작품을 배치합니다. 6개를 넘으면 전시실 버튼으로 방을 선택합니다. 현재 방의 이미지 자원만 준비하고, 실제 이미지가 없거나 불러오지 못하면 이름·역할이 있는 표지를 유지합니다.

작품 패널을 선택해 정보를 확인한 뒤 **선택한 작품 상세 보기**를 누릅니다. 바닥의 초록 이동 지점 또는 작품 바로가기 목록을 선택하면 그 구역으로 이동합니다. 드래그로 시점을 바꾸고 휠·두 손가락으로 확대합니다. 자유 보행은 제공하지 않습니다. **로비로 이동**하면 기본 시점으로 돌아옵니다.

상세에서 **전시장으로 돌아가기**를 누르면 전시실·선택·실제 카메라 위치와 방향을 복원합니다. 이전/다음 작품을 보는 동안에도 출발 전시장의 복귀 대상을 유지합니다. 갤러리에서 열었거나 새 페이지에서 상세 주소로 직접 들어온 경우에는 갤러리로 돌아갑니다. 시점과 이동 설정은 현재 페이지 메모리이며 새로고침 후에는 기본 전시실에서 시작합니다.

**이동 애니메이션 줄이기**와 시스템의 동작 줄이기 설정을 적용합니다. 여러 이동 요청은 현재 시점에서 최신 목적지로 변경합니다. 이동 중에는 상세 진입을 잠시 막고, 비활성 문서에서는 프레임을 멈춥니다. 모바일 페이지 스크롤은 공간 밖에서 사용할 수 있습니다. 3D 실패 시 작품 목록과 갤러리를 유지하고 재시도를 제공합니다.

개발 도구의 **기획 예시 전시장 미리보기**는 확인된 세 작품 이름·장르·역할로 동작을 검증하는 예시이며 실제 이미지를 추정해 채우거나 자동 공개하지 않습니다.

## 초기 갤러리 보존

처음 만든 정적 갤러리는 [legacy/static-gallery/index.html](./legacy/static-gallery/index.html)에 보존했습니다. 확인된 세 작품 SpaceShipThree, 난장판!, Eternal_Steam을 표시하는 이전 초안입니다. 현재 플랫폼의 공개 콘텐츠로 자동 등록하지 않습니다.

이전 초안을 보려면 별도 터미널에서 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory legacy/static-gallery
```

현재 폴더는 아직 Git 저장소나 실제 GitHub Pages 주소에 연결되어 있지 않습니다.


## 초기 로딩과 공유 링크

갤러리에서 작품 상세·그래프·전시장·편집기 코드는 방문할 때 불러옵니다. Three.js는 3D 보기 선택 후, YouTube는 재생 선택 후 내려받습니다. 브라우저의 자료 검증 함수는 매 빌드에서 Schema로 생성하며 Node 검증과 결과를 비교합니다. ZIP 처리도 관람 초기 코드에서 제외했습니다.

공개 빌드는 전시장 제목·제작자·설명에서 Open Graph와 큰 이미지 카드 메타데이터를 생성합니다. 공개 작품별로 `share/<slug>/` 주소와 1200×630 JPEG 카드도 생성합니다. 대표 이미지가 없으면 제목과 제작자 이름으로 카드를 만듭니다. 공개 갤러리·전시장·상세의 링크 복사 버튼을 사용하세요. 초안/개발 미리보기에는 배포 링크 복사 버튼이 표시되지 않습니다.

```sh
PAGES_BASE=/portfolio/ PAGES_URL=https://YOUR_ACCOUNT.github.io/portfolio/ npm run build
npm run performance:check
```

위 계정/주소는 자신의 실제 주소로 바꿉니다. PAGES_URL이 없는 로컬 빌드는 URL을 추정하지 않고 canonical/og:url을 생략합니다. Linux에서 한국어 공유 카드를 빌드하려면 Noto CJK 같은 한국어 글꼴이 필요하며 CI에는 fonts-noto-cjk 설치를 연결했습니다. 성능 비교와 검사 한계는 [기술 기록](./docs/technical-plan.md)에 정리했습니다.


## 큰 자료 성능 확인

```sh
npm run performance:large
```

격리된 프로덕션 빌드/Chromium에서 50·200노드의 2D/3D, 고해상도 이미지 검사와 약 24MiB ZIP을 3회 측정합니다. 결과는 test-results/performance-large.json과 atlas PNG에 저장됩니다. 같은 Blob의 이미지 검사 재사용, 큰 그래프 편집 폼 지연 생성·2D 도형 재사용, 3D 라벨 atlas·선/화살표 묶기와 큰 ZIP Worker 처리를 적용했습니다.

CI에서는 시간 대신 실제 자원 상한과 정리·Worker 사용, 200노드 선택/왕복·편집 폼 입력/오류 보존, 큰 ZIP 취소/CRC/Worker 오류의 초안 보존을 확인합니다. 전체 완료 시간과 UI 타이머 지연을 구분한 [측정 결과와 한계](./docs/technical-plan.md)를 참고하세요.


## 밝은 테마와 동작 피드백

기본 전시장과 새 초안은 밝은 오로라 글래스 테마를 사용합니다. 라벤더·아이스 블루 배경과 유리 패널을 갤러리·상세·편집 화면에 연결했습니다. 세 작품 이상이면 첫 작품을 크게 보여주고, 좁은 화면에서는 한 열로 전환합니다. 입력과 본문은 읽기 쉬운 면을 유지하며 모바일의 넓은 블러는 줄입니다. 2D/3D 그래프·3D 전시장·공유 카드에도 같은 밝은 색상 계열을 적용하며 기존 digital 자료와 테마 선택은 유지합니다. [시안 비교와 구현 검토](./design-qa.md)

메뉴 전환, 클릭·키보드 실행, 입력/오류, 선택, 작품 추가·순서 변경, 상태 알림, 대화상자·펼침과 미리보기에 짧은 모션을 적용했습니다. 동작을 애니메이션 뒤로 미루지 않으며, 시스템의 동작 줄이기를 선택하면 CSS·Web Animations 모두 중지합니다. 사용자가 선택한 프로젝트 데이터나 미저장 입력을 바꾸기 위해 화면을 재생성하지 않습니다.
