- 공개 조건 중첩 스키마에 object·array 타입을 명시한 뒤 기존 Python 검사 26개를 다시 통과했다.
- `npm test`: 77개 통과, 실패 0개. 형식, R01–R15의 관계 규칙, 생성·조회, 공개 선별 및 해시 라우팅을 검사했다.
- `npm run build`: TypeScript 검사와 앱 빌드 통과. 공개 앱 JS는 약 225kB, gzip 약 71kB이며 Three.js는 아직 포함하지 않았다.

### 검사한 핵심 동작

중복 작품·slug·그룹·노드·연결·사례·자산, 전시 순서 누락과 중복, 잘못된 그래프 연결 및 자산 참조를 검출한다. 부모 자기 참조와 순환은 거부하고 일반 연결 순환은 허용한다. 자기 참조 연결선은 안내로 반환한다.

기간 순서, 진행 중 종료월, 인증정보가 들어간 URL, 공개 노드의 기여 설명과 구조 근거를 검사한다. 실제 윤년 날짜 및 유니코드 코드 포인트 길이를 검사하며 필드 제거·기본값 삽입·타입 변환을 하지 않는다. 오류에는 안정적인 작품·시스템·자산 이동 대상 ID를 제공한다.

공개 정리는 원본을 바꾸지 않고 공개 작품, 확인한 그래프와 사용 중인 자산만 남긴다. 프로젝트 순서를 유지하며 초안만 있으면 빈 public 자료를 만든다. 기획 예시의 공개 전환은 거부한다. 확인한 그래프의 오류는 공개를 막는다.

### 브라우저와 앱 출력

Codex In-app Browser에서 세 예시의 검사 통과를 확인했다. 없는 연결선 도착 노드는 R07로 안내되고, 기획 예시는 공개가 거부된다. 프로필을 입력한 세 작품 초안은 공개 작품 0개, 한 작품을 공개 대상으로 바꾸면 1개로 선별된다. 등록되지 않은 영상과 그래프는 안내이며 다른 자료를 막지 않는다. 확인한 흐름에서 콘솔 오류는 없었다.

루트와 `/Project_IO/` base 앱 빌드를 확인했다. 하위 경로의 설정 주소를 직접 열고 새로고침한 후 갤러리로 이동했다. 모바일 360px 화면에서 가로 넘침 없이 빈 전시장을 표시했다. 공개 출력에는 docs, spec, legacy, vendor, 개인 예시와 개발 검증 도구가 없다.

### 아직 확인하지 않은 영역

R10 중 ID·경로·파일명·MIME 메타데이터 일치는 구현했지만 **실제 이미지 파일의 존재와 바이트 형식·크기·치수 검사는 다음 단계**다. 현재 공개 선별은 JSON 함수이며 실제 ZIP 내보내기나 배포 완료를 뜻하지 않는다.

IndexedDB 저장, 이미지와 입력 원문을 포함한 백업 복원, 실제 관람과 편집기, YouTube 재생, 2D·3D 렌더링 및 실제 GitHub Pages·다른 계정 재사용은 아직 구현·검증하지 않았다. 현재 앱 화면은 기반과 준비 안내이며 작품 데이터 로더도 후속 단계다.

## 저장과 패키지 구현 검증 · 2026-10-06

기반 단계의 기록 뒤에 추가한 결과다. 현재 자동 검사는 총 **102개 통과, 실패 0개**이며 TypeScript 검사와 앱 빌드를 통과했다. fflate 0.8.3으로 ZIP을 처리하고 테스트에서는 fake-indexeddb 6.2.5와 pngjs 7.0.0을 사용했다.

### 저장과 실패 보존

데이터와 이미지 Blob을 같은 transaction으로 저장하고 실제 complete 이후에 성공을 반환한다. 마지막 put이 성공한 뒤 강제로 transaction을 abort하는 검사에서 이전 자료와 이미지 바이트가 남았다. 연속 저장은 호출 시점의 스냅샷을 순서대로 반영하며 오래된 revision을 거부한다. 저장 중 추가 편집은 미저장 상태로 남는다.

서로 다른 base의 저장 키가 다르고, 가져오기·취소·검사 실패 및 교체 저장 실패가 현재 자료를 바꾸지 않는 것을 확인했다. 이미지와 pendingInputs가 전체 백업 및 저장에서 유지되며 대상이 없는 원문은 안내하고 다른 항목에 자동 적용하지 않는다.

### 이미지와 ZIP

실제 PNG를 디코딩해 파일의 바이트 수, 형식과 2×3 픽셀 크기를 확인했다. 누락·추가 파일, MIME·크기·치수 불일치, 가짜 PNG·잘린 이미지와 입력 한도를 검사했다.

전체 백업 왕복에서 모든 작품, 이미지 바이트와 잘못된 영상 URL 원문 및 편집 상태가 보존되었다. 공개 패키지는 공개 작품·확인 그래프와 사용 이미지뿐이며 원본을 보존한다. 공개 대상의 미정리 입력은 막고, 제외한 초안과 미확인 그래프의 원문은 백업에 남긴다. 공개 그래프의 작품 ID별 파일도 왕복 확인했다. 예시 백업은 example 종류를 유지하며 공개가 거부된다.

manifest 버전·파일 수·바이트 수, 숨긴 자산 누락, 예상 밖 파일, 경로 탈출·중복 파일, 압축 전 크기와 손상된 CRC32 및 잘못된 UTF-8 JSON을 검사했다. 출력 ZIP은 동일한 가져오기 검사를 다시 통과해야 사용자에게 제공한다.

### 실제 브라우저 흐름

사용 중인 주소와 분리한 로컬 origin/base에서 테스트했다. 인앱 브라우저에서 이름과 실제 PNG를 저장한 뒤 새로고침하여 같은 이름과 2×3 이미지가 복원되었다. 다운로드한 이미지 포함 백업을 다시 가져와, 취소 시 편집 중 이름이 유지되고 확인 시 이름·이미지가 복원되는 것을 확인했다.

잘못된 경로를 가진 ZIP은 거부되었으며 현재 이름이 유지되었다. 세 작품과 세 이미지 및 입력 원문 하나를 가진 백업을 가져온 뒤 다시 백업해 내려받은 실제 ZIP에서 작품 3개·이미지 3개와 같은 원문을 확인했다. 공개로 선택한 작품 한 개의 공개 ZIP에는 작품 1개와 사용 이미지 1개, 입력 원문 0개만 있었다.

인앱 브라우저와 Chrome에서 실제 Downloads 파일을 확인하고 재검사했다. 도구의 download 이벤트 대기는 시간 초과가 났으나 파일 다운로드는 완료되었으며, 파일 내용 검사로 판정했다. Chrome의 파일 업로드 자동화에는 확장의 파일 URL 권한이 필요해 설정을 변경하지 않고 인앱 브라우저로 업로드·복원을 확인했다.

모바일 360px 설정 화면에서 가로 넘침이 없었다. 확인한 인앱 흐름에서 콘솔 오류와 경고는 없었다. 공개 빌드에는 개인 예시와 개발 검증 도구가 포함되지 않는다.

### 남은 검증

이 단계에서 실제 PNG를 확인했다. JPEG·WebP·AVIF와 다른 OS 및 모든 브라우저 조합의 실제 파일 검증은 남아 있다. 실제 갤러리·작품 상세, 전체 편집기, YouTube, 2D·3D와 실제 GitHub Pages·다른 계정 재사용은 아직 완료하지 않았다.

- 저장된 session에서 편집 화면 위치만 바꿔도 콘텐츠는 같지만 revision과 dirty가 바뀐다.

저장 재현은 실제 사용자 IndexedDB 대신 독립 메모리 DB를 사용했고 관람 검증은 개인 초안을 저장하지 않는 기획 예시 미리보기에서 수행했다. 실행 코드나 기존 자동 테스트를 수정하지 않았다. 재현 조건·관련 코드와 개선 완료 기준은 [전체 구조 평가](../docs/structure-review.md)에 기록했다.

2026-10-14 후속 가독성 적용: CSS의 작은 기능 문구·도움말 14px, 항목명 15px/600, 입력 16px와 불투명한 글자 색을 실제 브라우저 computed style로 확인했다. 약 95% 흰 캡션의 최저 합성 배경을 가정한 대비 계산은 제목 13.85:1/보조 6.69:1이며 전체 앱 접근성 적합성을 뜻하지 않는다. 360px에서 긴 작품명의 중간 줄바꿈을 발견해 420px 이하 세로 카드, 1000px 이하 한 열을 적용했다. 재캡처와 DOM에서 360px/720px 가로 넘침 없음과 작품명 한 줄을 확인했다.
