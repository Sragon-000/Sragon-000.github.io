# 초안 저장과 파일 패키지 사용 안내

현재 설정 화면에서 이름과 전시장 이름, 프로필 이미지를 입력하고 초안을 저장하거나 파일로 옮길 수 있다. 갤러리·상세 미리보기와 가져온 작품의 영상 주소 입력도 사용할 수 있다. 작품 추가·수정·삭제와 이미지·개발 사례·구조 목록 및 전시 설정 편집도 연결했다. 자료를 직접 준비한 경우 portfolio.json 또는 ZIP으로 가져올 수 있다.

## 이 기기에 저장

초안과 아직 정리되지 않은 입력 원문, 이미지 Blob을 IndexedDB의 같은 transaction에서 저장한다. put 요청만 성공했을 때 저장 완료라고 표시하지 않으며 transaction 완료를 확인한다. 실패하거나 취소되면 이전 저장본이 남는다. 저장 중 새 편집은 저장한 revision과 구분해 미저장 상태로 표시한다. [IndexedDB transaction 안내](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction)

초안은 origin과 정규화한 배포 base 경로로 구분한다. 같은 GitHub 계정의 다른 저장소 사이트가 초안을 공유하지 않는다. 이름을 바꾸어도 저장소 키는 바뀌지 않는다. 개발 주소, 배포 주소와 다른 브라우저는 별도 초안이므로 백업 파일로 옮긴다.

현재 간단한 이름 입력도 길이와 형식을 검사한다. 표준 자료에 넣을 수 없는 원문은 마지막 유효 값과 분리해 저장한다. 전체 백업에는 그 원문이 남지만 공개 대상의 미정리 입력은 해결해야 공개 파일을 만들 수 있다.

## 저장 충돌과 읽기 실패 복구

같은 초안을 두 탭에서 열면 각 탭은 처음 읽었던 저장본의 버전을 기억한다. 저장 트랜잭션 안에서 그 버전과 현재 저장본이 일치할 때만 기록한다. 다른 탭이 저장하거나 파일 가져오기로 교체한 경우에는 이 탭의 저장을 막으며 입력·이미지는 메모리에 유지한다. 편집 횟수가 더 많다는 이유로 다른 탭의 저장본을 덮어쓰지 않는다.

충돌한 탭에서 **전체 초안 백업**을 생성하고 다운로드해 입력을 보관할 수 있다. **저장본 다시 읽기**를 선택하면 미저장 내용을 교체한다는 확인을 보여준다. 취소하면 입력을 유지하고, 확인한 뒤 읽기에 성공했을 때만 새 저장본을 적용한다. 다시 읽기에 실패하면 현재 입력을 유지한다.

초안을 처음 읽는 데 실패한 상태는 새 빈 초안과 다르다. 편집·저장·빈 백업을 막고 기존 데이터베이스를 유지한다. **저장본 다시 읽기**로 다시 시도하거나, 보관한 백업을 가져와 확인 후 기존 저장본을 교체할 수 있다. 가져오기 확인을 기다리는 동안 다른 탭에서 저장본이 바뀌어도 교체를 거부한다. 기존 저장본의 버전을 확인할 수 없는 경우에는 파일 교체도 진행하지 않는다.

편집 화면 위치만 바꾸는 것은 콘텐츠 변경으로 표시하지 않는다. 화면 위치는 다음 수동 저장/백업에 포함되지만 화면 이동만으로 이탈 경고나 공개 다운로드 링크 무효화가 발생하지 않는다.

## 백업과 공개 내보내기

**전체 초안 백업**은 모든 작품과 그래프, 사용하지 않는 이미지까지 포함한다. 편집 상태와 잘못된 입력 원문도 보존한다. ZIP 안에는 portfolio.json, backup.json, assets 파일과 export-manifest.json이 있다.

**공개 콘텐츠 내보내기**는 published 작품, 해당 작품의 verified 그래프와 참조하는 이미지만 포함한다. 기획 예시는 공개하지 않는다. 선택 자료가 없으면 올바른 프로필을 가진 빈 전시장을 만들 수 있다. 영상과 그래프가 없는 작품에는 안내를 표시한다.

공개 ZIP은 content/site.json, content/projects.json, content/assets.json, 필요한 content/architectures 파일과 assets 및 export-manifest.json을 포함한다. 원본 초안과 그 공개 선택을 수정하지 않는다.

두 내보내기는 생성한 ZIP을 동일한 가져오기 검사로 다시 확인한 뒤 다운로드 링크를 제공한다. **ZIP 다운로드** 링크를 선택해 파일을 받는다. 파일 생성, 다운로드와 실제 사이트 배포는 별도 단계다. 공개 파일 로더와 GitHub Pages 워크플로를 연결했다. 공개 ZIP은 content:import 명령으로 검증한 뒤 site-content에 반영하며 실제 업로드와 배포는 별도다. [배포 절차](./github-pages-guide.md)를 따른다.

## 가져오기와 전체 교체

1. **백업 또는 콘텐츠 가져오기**에서 ZIP 파일을 선택한다.
2. 버전, 경로, 파일 목록·크기·CRC32, 자료 구조·참조와 이미지 실물을 검사한다.
3. 제작자와 전시장 이름, 작품·이미지·입력 원문 수를 미리 보여준다.
4. 필요하면 **현재 초안 백업**으로 기존 편집을 보관한다.
5. **현재 초안 대신 가져오기**를 선택하면 가져온 자료와 이미지를 함께 저장한다.
6. 저장 성공 후 화면을 교체한다. 실패하면 기존 초안을 유지하며, **취소하고 현재 초안 유지**도 가능하다.

공개 ZIP을 가져오면 자료를 로컬 workspace로 편집하며 published 작품 상태는 유지한다. 예시 백업은 example 표시를 유지한다. 가져오기가 실제 GitHub 저장소를 수정하지는 않는다.

일반 JSON을 가져올 때 이미지가 있으면 **JSON과 이미지 파일로 가져오기**를 펼쳐 먼저 이미지를 선택한다. 파일명은 자료의 assets 경로 마지막 파일명과 맞아야 한다. JSON을 고르면 함께 검사한다. 이미지가 빠지거나 같은 파일명으로 중복되면 안내한다.

## 이미지와 패키지 한도

이미지는 PNG, JPEG, WebP와 AVIF이며 파일당 최대 10MiB, 4천만 픽셀 이하다. 브라우저와 빌드에서 같은 픽셀 한도를 적용한다. 확장자나 선언한 MIME만 믿지 않고 파일 시그니처와 실제 디코딩을 확인한다. 바이트 수와 디코딩한 가로·세로가 자산 기록과 같아야 한다. 지원되지 않거나 손상된 파일은 입력을 유지한 채 오류를 표시한다. [브라우저 이미지 디코딩 안내](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap)

ZIP은 최대 64MiB, 압축 전 합계 128MiB와 최대 512개 파일을 지원한다. JSON 한 파일은 2MiB 이하다. 일반 단일 ZIP의 저장·deflate 압축을 지원하며 암호화와 ZIP64 및 분할 ZIP은 지원하지 않는다. 임의 실행 파일이나 부모 경로, 절대 경로와 중복 파일을 허용하지 않는다.

manifest는 자기 자신을 제외한 정확한 파일 목록과 바이트 수를 기록한다. 추가 파일을 조용히 버리지 않고 오류로 표시한다. ZIP 처리에는 [fflate](https://github.com/101arrowz/fflate)를 사용하며 앱은 압축 생성 후 전체 검사를 다시 수행한다.

## 확인한 범위

[검증 기록](../spec/verification.md)에 자동 검사 102개와 실제 브라우저 결과를 기록했다. 실제 PNG로 새로고침 복원과 이미지 포함 백업 왕복을 확인했다. Chrome과 인앱 브라우저에서 생성한 다운로드 파일을 실제로 읽어 검사했다. 브라우저의 자동 다운로드 이벤트 대기는 도구에서 시간 초과가 발생했으나 파일은 Downloads에 생성되었으며, 다운로드된 파일을 다시 읽어 확인했다.

실제 모든 이미지 형식과 모든 브라우저·OS 조합을 확인한 것은 아니다. 갤러리·상세와 작품 편집기 및 YouTube 연결은 구현했다. 실제 프로젝트 영상 검증, GitHub Pages 배포 및 다른 계정의 템플릿 재사용은 후속 단계다.


## 편집 화면에서 시작하기

기본 정보에서 제작자와 전시장 이름을 적고, 작품 관리에서 작품 추가를 선택한다. 제작 정보와 이미지·영상, 개인 기여·개발 사례를 작성하고 공개 대상을 선택한다. 목록에서 위로·아래로 이동해 전시 순서를 정한다. 상단 도구로 저장하거나 미리 본다. 전시 설정에서는 설명과 테마·로고·아이콘을 선택한다. 마지막으로 내보내기 화면에서 공개 작품 수와 절차를 확인한다.

이미지는 대체 설명을 먼저 입력하고 파일을 선택한다. 아직 파일을 선택하지 않은 이미지 설명은 현재 페이지의 메모리에만 남고 저장·백업 자료에는 포함하지 않는다. 작품 사이를 이동해도 설명이 다른 작품에 적용되지 않는다. 등록한 이미지 설명과 파일은 실제 자료에 포함된다.

삭제 전 이름과 참조 정리 범위를 보여준다. 직전 삭제는 바로 되돌릴 수 있고 다른 콘텐츠 편집이나 새로고침 이후에는 종료된다. 삭제 후 배포 사이트는 자동으로 바뀌지 않는다. 전체 백업은 되돌리기와 별개로 파일로 보관할 수 있다.

보관된 미정리 입력 목록에서 과거 원문을 확인한다. 그 필드에 유효 값을 입력하면 해당 원문을 정리하고, 대상이 없는 원문은 명시적인 제거 확인으로 정리한다. 공개 대상의 오류는 해결한 뒤 공개 ZIP을 생성한다.


## 구조를 미리 보기

작품 편집의 그룹·시스템·연결 목록을 입력한 뒤 초안 포함 미리보기를 사용한다. 작성 중인 구조도 2D·3D로 탐색할 수 있다. 확인일과 근거·기여 설명을 준비하고 구조 확인을 선택하면 공개 대상의 확인 그래프로 내보낼 수 있으며, 공개 필수값은 내보내기 때 다시 검사한다. 실제 구조의 정확성은 작성자가 코드와 자료로 확인해야 한다.

그래프의 선택·강조·카메라·확대 값은 현재 페이지 메모리에서만 유지한다. 저장/백업이나 공개 ZIP의 내용은 바뀌지 않는다. 이미지·입력 원문과 마찬가지로 실제 구조 자료는 기존 자료 계약으로 저장한다.


## 공간 관람과 저장의 구분

3D 전시장은 공개 대상 또는 초안 포함 미리보기의 같은 작품과 순서를 읽는다. 여섯 작품마다 전시실을 나눈다. 구역 선택·카메라·이동 설정은 페이지 메모리이며 이 기기 초안 저장·백업의 내용을 바꾸지 않는다. 상세에서 전시장으로 돌아오면 마지막 관측 시점을 복원하고, 새로고침하면 기본 시점으로 시작한다.

실제 자료가 없는 작품은 이름 표지를 사용한다. 3D 연결이 끊겨도 목록에서 작품을 선택하고 상세를 열 수 있다. 공개 내보내기는 이미지와 데이터만 포함하며 전시장 관람이나 ZIP 다운로드로 실제 GitHub 사이트를 게시하지 않는다.
